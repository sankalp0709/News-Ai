## 12. Replay Participation

Replay functionality is operational in the current runtime.

The runtime generates an input fingerprint and uses it to determine
whether an input has already been processed.

### Demonstrated behaviour

First execution:

    REPLAY MISS

The input is processed and stored.

Repeated execution with the same input:

    REPLAY HIT

The same input fingerprint is recognized and replay information is
returned.

Example execution evidence demonstrated:

    Replay MISS
    input_fingerprint: sha256:<fingerprint>

followed by:

    Replay HIT
    input_fingerprint: sha256:<same fingerprint>

This provides deterministic replay behaviour for repeated identical
inputs.

## 18. Deterministic Execution

Repeated execution using the same image has been tested.

    → Replay MISS

    → Artifact stored

    Second request with same input
    → Replay HIT
    → Existing replay information reused
    → Artifact persistence performed

The same input fingerprint was observed for both executions.

    Samachar
        ↓

A successful Bucket response has been observed containing:

- `artifact_id`
- `hash`
- `parent_hash`
- `timestamp`
- `storage_type`
- success status
